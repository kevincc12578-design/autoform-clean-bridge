公共 API 和 JSON CLI 已调用同一生命周期层。CLI 提供 `audit`、只读 `discover`、`capabilities`、`lifecycle --live`、等价的 `call lifecycle --live --request` 和 `batch --live --request`。单项工程修改只允许在同一批处理会话内使用，后续步骤可通过 `@alias` 引用先前创建的工程，句柄由 Bridge 内部保存和更新，不从文件名重建所有权。输出目录必须全新；启动前后隔离审计和失败结果都会落盘。

## 工程所有权与生命周期门禁

附着时记录已打开工程基线，不按工程名称或 `Untitled_*` 前缀取得所有权。新工程必须来自本次明确操作前后的唯一新增页签。适配器将当前 UIA RuntimeId 与会话内生成的工程 token 关联；关闭后删除 live 映射，核心将旧 token 退役，禁止旧句柄继续保存或关闭其他工程。

每轮最多保留一个自有工作工程。生命周期核心要求：

1. 记录用户基线、开始工程数和内存检查点。
2. 创建唯一新工程，读出非空语义数据。
3. 保存到本轮全新工作文件，核对目标路径与保存状态证据。
4. 关闭该自有页签，并从最新工程清单确认 token 消失。
5. 核对保存文件哈希，重开刚才的同一个文件。
6. 对比保存前与重开后的语义读回。
7. 通过正常保存路径再次保存并关闭，确认自有工程数为零。
8. 验证基线工程仍保留，收集结束资源检查点，停止自有 worker。

`lifecycle_ok` 要求保存、首次关闭、同文件重开、读回、最终关闭、清理、基线保留和 worker 停止等门禁全部通过；自有及未知新增工程数量均必须为零。P1 没有求解验收，`e2e_ok=false`、`solver_verified=false`，即使生命周期成功也不会升级为完整抱箍链通过。

保存或关闭不确定时不选择“不保存”。已确认属于本轮的内容可另存到全新诊断文件后再关闭；归属不明、未知模态或新增工程不明确时保留现场并报告。清理未确认成功就阻止下一轮，不批量关闭名称相似的页签。

## 保存和路径证据的真实含义

当前 R13 的脏标记未直接暴露，`Design.dirty` 保持 `None`。`save_verified` 是以下组合证据的结果：

- 文件框中明确提交的完整绝对路径及提交前读回。
- 当前自有页签 RuntimeId 与活跃工程标题的对应关系。
- 文件框和模态结束、主窗口恢复可操作。
- 目标文件存在、内容可哈希。
- 后续真实关闭该页签后，从同一路径重开并核对语义。

这不是通过 AFD SDK 直接读取出的工程全路径，也不是独立观察到的 `dirty=False`。仅有文件大小、mtime、按钮点击成功或输入框值正确都不足以完成这套证明。未更改内容的正常保存可能不改变大小或 mtime，不以此单独判失败。

当前 P1 语义读回限定为空工程界面明确显示的零件、模具、坐标系、曲线和点数量。要求唯一可见、位于当前窗口区域的显式计数，不把“没找到控件”推断为零。非空模型、材料、工序或求解结果尚不属于此读回场景。

第 05 轮暴露 Shell 文件框的 UIA `AutomationId` 读取失败。当前文件框实现改用原生 `EnumChildWindows` 和 `GetDlgCtrlID` 定位核心控件，避免遍历 Shell 项目。第 06 轮在输入路径后过早读回，重开阶段失败；后续改为最多 3 秒的有界观察等待完成，不重复输入路径。第 07 轮验证了保存、原页签关闭、同文件重开读回及最终关闭全部通过；这仍仅限当前空工程场景。

## 启动、取消与资源

默认附着已有唯一 R13；需要创建应用进程时必须显式 `launch=True`。`license_server` 只覆盖本次应用子进程环境，不改系统环境、许可证服务或认证设置。只有本次新启动并显式 `allow_selected_license=True`，才允许点击已观察到的当前许可证方案“应用”按钮；不改选项，附着已有会话不会执行这一动作。

欢迎框关闭同样要求已观察到准确窗口类型、唯一按钮、相同 PID/创建时间并持有单写锁。未知启动窗口只读留证并返回 `needs_user`。`disconnect` 只停止本桥接的 worker、释放写锁；不等于关闭工程或退出 R13。

监督器为每次 worker 创建私有 Windows Job Object，先挂起创建根进程、分配至 Job，再恢复执行，并启用 kill-on-close。这样能覆盖 Python venv redirector 及其实际解释器子树；超时、`KeyboardInterrupt` 和正常根进程退出后遗留子进程都会触发有归属的回收。R13 应用和无关进程不加入该 Job。终止未确认时阻止新写入，不扩大到终止整个 R13。

`runs/worker-tree-selftest-20261028-01/result.json` 记录 4 项真实无 UI 测试全部通过：超时回收、`KeyboardInterrupt` 回收、正常父进程退出后遗留子进程回收、无关进程保护。每例记录观察到的 redirector/解释器身份及 Job 关闭后活动进程数为 0，`application_terminated=false`。该原件记录了受测源码版本，且当时 `source_matches_installed=false`；它证明所记录源码的进程树行为，不单独证明当时安装副本与源码一致。

资源记录为生命周期检查点的工程数、工作集和专用字节；峰值是这些检查点的最大值，不是持续采样得到的系统全程峰值。自有页签归零证明工程清理，不能据此承诺内存回到固定值；工作集下降也不能替代工程关闭证明。
