# AutoForm 自动化：项目方法与可复用工作流

整理日期：2026-10-31。本文总结 AutoForm R13 Bridge 项目中形成的工作方法，以及它们在抱箍场景中的应用。方法可以用于规划其他工艺的自动化；具体零件、参数、界面布局和验证结论仍须在新场景中单独确认。本文是方法总结，不是新的现场验收报告。

## 1. 核心方法

### 从真实演示建立步骤依据

先由熟悉工艺的人员演示目标流程，再关联视频、原始鼠标与快捷键事件、窗口和控件观察、前后截图与采集时间，整理出可追溯的步骤。每一步记录前置条件、操作对象、动作、预期结果和证据。

录制器只采集，不替用户执行操作。每次录制使用独立目录，保留原始数据和时间映射。控件观察缺失或同步存在不确定度时，应说明缺口，并以视频和事件核对，不能补造控件名称或操作结果。普通键入字符不作为键盘事件记录，但屏幕上可见的文字仍可能进入视频和截图。

### 用业务后置条件判断成功

输入已发送只能证明输入层动作。业务操作应根据其可观察结果判断：

| 操作 | 主要验证方式 | 范围边界 |
| --- | --- | --- |
| 设置冲压方向 | 读回实际方向角；保存重开后比较 | 菜单点击或标签本身不能证明角度已持久化 |
| 添加材料 | 核对材料与板厚，等待相关弹窗和编辑器结束 | 正确进入材料页面不等于设置完成 |
| 执行成型检查 | 核对本次有效结果，或结合本次计算状态变化与结果判断 | 页面出现不等于计算完成 |
| 分配工序区域 | 核对当前工序、目标区域及可观察的分配状态 | 局部界面图案不等于全部工艺语义均已读取 |
| 提交料片 | 核对提交、持久化及后续几何输入 | 提交不等于完整闭合拓扑已读出 |
| 启动求解 | 将本次工程路径、作业和原生日志绑定并核对结果 | 任务提交或服务完成不等于所有求解阶段成功 |
| 保存工程 | 关闭后重开同一文件，读回关键业务值 | 文件存在或修改时间变化不能单独证明保存完成 |

前置条件失败时，依赖它的后续步骤应标为未验证或 `skipped_dependency`。未知值明确标为未知，不用零或假值代替。

### 区分不同层次的状态

- 打开模面编辑器不等于生成了模面；工具显示不等于工具已启用。
- 断开自动化连接不等于工程已关闭；求解器关闭结果文件的日志不等于 GUI 页签已关闭。
- 求解结束和 Springback 阶段成功，不等于回弹量已读出，也不等于产品满足工程公差。

每项结论都应注明它的验证范围。输入成功、业务状态、持久化、求解和工程判定分别留证。

### 将业务流程与底层操作分层

```text
业务工作流
    ↓
公共 Bridge API / CLI
    ↓
会话、工程、工艺、求解、证据等操作
    ↓
窗口、UIA、输入和原生作业适配
```

公共操作应返回操作名称、请求及工程或作业标识、结果、后置条件、验证范围、证据、错误和耗时。业务工作流通过公共操作组合流程，避免把判断散落在一串不可检查的点击中。实际接口以[API 文档](api.md)为准。

### 把所有权与收尾作为正式业务步骤

附着会话时先记录用户已有工程，再登记本轮自有工程的身份与路径；仅对身份明确的自有工程执行保存和关闭。推荐顺序：

```text
记录用户工程基线
→ 创建或打开本轮自有工程
→ 保存并确认保存事务完成
→ 关闭指定工程并确认页签消失
→ 重开刚保存的同一文件并读回关键内容
→ 再次关闭
→ 核对本轮自有页签归零，用户基线保留
```

清理未确认成功时停止下一轮。失败或超时后，尽可能保存本轮诊断内容，停止自有写入进程，并分别报告求解作业是否仍在运行。附着的 AutoForm 不应被当作自有工作进程随意终止。

### 保留版本与原始证据

每轮使用独立输出目录，关联输入哈希、代码或安装版本、阶段结果、截图与控件观察、工程和作业标识、原生日志及重开读回结果。必要时独立解析原始日志；已发生错误、未知状态和失败阶段也应保留。

能力清单分别记录实现范围、最近验证版本和本次是否复验。旧版通过可以作为证据，不能自动转化为当前版通过。

## 2. 可复用工作流

### A. 从人工演示到新功能

1. 明确零件、软件版本和工艺目标，准备独立工程及输出位置。
2. 被动录制一次完整真实演示，并保留原始事件和截图。
3. 关联时间线、视频与控件观察，区分确定事实、推断和证据缺口。
4. 对每一步定义前置条件、动作、真实后置条件及对应证据。
5. 将动作实现为可单独调用的公共操作，再组合为业务流程。
6. 在适用的自有工程或阶段副本中验证，并完成保存、关闭和必要的同文件重开检查。
7. 更新能力范围、验证版本和待解决问题；后续完整场景再做整链验收。

### B. 抱箍仿真案例

本案例使用指定抱箍 STEP、S355MC 材料、4 mm 板厚与 AutoForm R13，步骤依据对应演示；其他输入和环境应另行验证。

1. 建立空工程并登记所有权，导入 STEP 并提取零件。
2. 自动设置冲压方向，再从方向菜单执行“反向”，读回方向角。
3. 设置材料和板厚，执行弯曲成型检查并核对结果。
4. 创建空规划，拖入 U 图标工序形成 C-20，并分配拉延区域。
5. 进入并离开模面编辑器；本路线忽略压料面，不生成压料面或补充面。
6. 创建平板料片，复制成型检查中的料片轮廓。
7. 在压机线设置库仑摩擦，核对 C-20 工具自动模型、接触与显示状态。
8. 添加参考模型，选择全部输入；参考模型不反转。
9. 创建测量方案并设置自由回弹，通过模拟 Start 启动作业，绑定本次工程和日志。
10. 核对原生输入及完整求解，随后完成保存、关闭、同文件重开读回和最终关闭。

普通另存不能替代模拟 Start 生成本次模拟输入。原生求解副本和 GUI 原工程也应标明各自角色，不能把副本结果误称为已回写原工程。详见[抱箍工序说明](抱箍工序说明.md)。

### C. 按批开发、分层验证

| 变更范围 | 验证方式 |
| --- | --- |
| 文档与能力清单 | 核对来源、链接及范围表述 |
| 单项参数或业务功能 | 参数检查、实际效果观察及必要读回 |
| 输入保护、所有权或保存关闭 | 针对受影响路径做小范围现场检查和必要失败检查 |
| 一批相互兼容的功能 | 分项读回，集中保存、关闭、重开同一文件并复核 |
| 完整整链交付 | 冻结版本，从三个独立空工程连续执行完整流程，逐轮核对求解与收尾 |

本项目完整整链的判据包括全部必需阶段通过、每轮少于 20 分钟、全程零人工点击、对应原生求解实际完成 Springback 且所有 `Program END` 代码均为 0，并完成工程保存关闭及收尾。局部验证可以证明局部能力，不能冒充完整整链。

## 3. 已有证据与适用边界

- 早期录像路线曾完成三个独立空工程的历史运行与求解；当时的重开采用副本，原工程关闭和最终关闭没有包含在该主链中。
- 新 Bridge 对指定抱箍案例有历史三轮业务验收和后续增量合并验收，包含同文件业务值核对与两次关闭。其结论仅适用于相应冻结版本、输入与环境，详见[增量合并记录](增量合并记录-2026-10-29.md)及[验收摘要](evidence/increment-merge-acceptance-2026-10-29.json)。
- 2026-10-31 的[详细功能树](AutoForm功能树-红绿黄灯详细版-2026-10-31.md)区分历史已验证、部分实现与待验能力。该文记录开发快照，不代表当时最新开发版已完成现场整链复验。
- 完整应力、应变、减薄和回弹数值场，以及按图纸公差自动判定产品是否合格，不能从求解成功直接推导。

项目的复用安排曾随要求调整：早期独立重建交接限制旧实现成为运行依赖；后续经项目维护者授权，选取部分已验证业务代码并在本包中维护。具体来源和边界见[复用边界](复用边界-2026-10-29.md)，不应把任何历史限制或通过状态无条件套用到其他版本。
